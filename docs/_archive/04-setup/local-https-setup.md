# Local HTTPS Development with mkcert

Track: B — Engineering Execution

This guide enables HTTPS for local development using **mkcert** — a tool that creates locally-trusted development certificates.

---

## Why Local HTTPS?

Modern web standards increasingly require HTTPS even in development:

- `SameSite=Strict` cookie policy (GitHub OIDC flows, secure sessions)
- HSTS (Strict-Transport-Security) headers
- Some APIs only accept HTTPS (webhooks, external integrations)
- **Production parity** — test the same TLS + HTTP/2 behavior as prod

---

## Local URL Switchers

Local HTTPS is only one URL mode. Use the shared helper so scripts, Bruno, smoke tests, and browser docs stay aligned:

| Mode | API base | API docs | Dashboard |
|---|---|---|---|
| Direct HTTP | `http://127.0.0.1:8000` | `http://127.0.0.1:8000/docs` | `http://127.0.0.1:8501` |
| Edge HTTPS | `https://127.0.0.1/api` | `https://127.0.0.1/api/docs` | `https://127.0.0.1/` |

```bash
# Direct HTTP (default)
just up
just api-check

# Edge HTTPS parity
just up-https
LOCAL_API_SCHEME=https just api-check
LOCAL_API_SCHEME=https just api-test
```

Override variables and the full matrix live in the Local URL Matrix guide.

## One-Time Setup

```bash
# 1. Install mkcert
sudo apt-get install -y mkcert libnss3-tools

# 2. Install local CA & generate certificates
mkcert -install
mkdir -p infra/certs
cd infra/certs
mkcert localhost 127.0.0.1 "*.local"

# 3. Start services and verify
just up-https
curl -vk https://127.0.0.1/api/api/v1/observations
```

## Architecture

```text
┌─ Your Browser ──────────┐
│   https://127.0.0.1:443 │
└──────────┬──────────────┘
           │ TLS/HTTPS
           ▼
    ┌──────────────────┐
    │  edge (reverse  │
    │   proxy on :443) │
    └──────┬───────────┘
           │ HTTP :8000/:8001/:8003/...
           ├─► ingestor:8000
           ├─► inference:8001
           ├─► dashboard:8003
           ├─► analytics:8005
           └─► [other services]
```

### TLS termination at edge means

- Browser ↔ edge: HTTPS (encrypted)
- edge ↔ services: HTTP (same Docker network, no encryption needed)
- Services don't need TLS configuration
- No application code changes required

## Certificate Details

### Viewing Certificate Info

```bash
openssl x509 -in infra/certs/localhost+2.pem -noout -dates
```

### Certificate Validity

- **Validity:** 825 days (auto-generated by mkcert)
- **Domains:** `localhost`, `127.0.0.1`, `*.local`
- **Trust:** Automatically trusted by your OS, all browsers, and Java

### Regenerating Certificates

If certs expire or you add a new domain:

```bash
cd infra/certs
rm -f localhost+*.pem
mkcert localhost 127.0.0.1 "*.local"

# Restart edge
docker compose restart edge
```

## Troubleshooting

### edge log shows `SSL_ERROR_RX_OBSERVATION_OVERFLOW`

**Issue:** Attempting HTTP on HTTPS port or port mismatch.

**Solution:** Use correct URL:

- ✅ `https://127.0.0.1` (443)
- ❌ `http://127.0.0.1:443` (won't work)

## CI/CD Note

### GitHub Actions & deployment environments don't need mkcert

- CI runners generate certs via Let's Encrypt or cloud provider CA
- Production uses externally-signed certificates
- mkcert is **dev-only** (browser/OS auto-trusts, saves time)

## Common Issues & Solutions
| Issue                          | Solution                                                                  |
| ------------------------------ | ------------------------------------------------------------------------- |
| Browser shows "Not Secure"     | Reinstall mkcert CA: `mkcert -install`                                    |
| `curl` against edge fails | Check certs: `ls infra/certs/*.pem` and use `curl -k https://127.0.0.1/api/health` |
| edge can't find cert file     | Verify docker-compose mounts: `docker inspect <edge-id>`                 |
| Port 443 already in use        | `lsof -i :443` to find process, then `kill -9 <pid>`                      |
| Certificate expired            | Regenerate: `cd infra/certs && rm -f *.pem && mkcert localhost 127.0.0.1` |
